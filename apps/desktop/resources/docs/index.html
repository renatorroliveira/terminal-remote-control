Terminal Remote Control user guide

Terminal Remote Control (TRC) runs terminal sessions on your Linux hosts and shows them in one accessible macOS window. The sessions belong to a small daemon, trcd, that the app installs on each host for your user, so a session keeps running when you quit the app or lose the network.

This guide covers Epic 1, which version 0.2 completes. What's not there yet lists what later releases add.

Requirements

On your Mac:

  • macOS on Apple silicon or Intel.
  • OpenSSH 8.5 or later. The one that ships with macOS works.
  • An SSH key that reaches each host, loaded in your SSH agent (ssh-add -l lists it). TRC never asks for passwords or passphrases.

On each host:

  • Linux on x86_64 or arm64.
  • sshd that accepts your key, and a POSIX shell.
  • A few megabytes free in your home folder, or in another folder you choose, that allows running programs (not mounted noexec), and sha256sum or shasum. The host needs no internet access, no root or sudo, and no packages.

TRC uses your own SSH setup: ~/.ssh/config (aliases, ProxyCommand, ProxyJump, ports, users), your agent and your known_hosts. It never changes your SSH configuration or your keys. The one file it writes is your known hosts file, the first UserKnownHostsFile your SSH config names (~/.ssh/known_hosts unless you set another), and only when you trust a new host key.

Install

  1. Download the release for your Mac from the Releases page: TRC-<version>-mac-arm64.dmg for Apple silicon, or TRC-<version>-mac-x64.dmg for Intel. SHA256SUMS.txt lists every file's checksum; with it in the same folder, shasum -a 256 --ignore-missing -c SHA256SUMS.txt checks that your download is complete and intact. It comes from the same Releases page, so it cannot show who made the files.
  2. Open the dmg and drag Terminal Remote Control to Applications.

  3. Open it once from Applications. 0.x releases are alpha, experimental builds: they are ad-hoc signed, not notarized, so macOS blocks the first launch. Signed builds start with 1.0.0. Open System Settings, then Privacy & Security, and choose Open Anyway next to the message about Terminal Remote Control. Or, in Terminal:

    xattr -dr com.apple.quarantine "/Applications/Terminal Remote Control.app"

Quick start with VoiceOver

VO below means the VoiceOver keys: Control-Option, or Caps Lock if you set VoiceOver to use it.

  1. Turn on VoiceOver with Command-F5, then open Terminal Remote Control. TRC notices VoiceOver, turns on screen-reader mode and says so.
  2. Press Command-F6 until VoiceOver says "Sessions and hosts", then press Tab until it says "New host". Type a host as you would after ssh, and press Return. TRC says each step of connecting.
  3. Press Command-T for a new session. Focus moves to its terminal, and VoiceOver says the session's name and host.
  4. Type commands as in any terminal. TRC speaks new output as it arrives and leaves out what you type, which VoiceOver already echoes. Press Control to stop VoiceOver speaking; Shift-Command-A mutes the session's output.
  5. To read what is on the screen, press VO-L for the line at the cursor. For everything, press Option-F2: review mode holds the whole scrollback as text that you read with the arrow keys and VoiceOver's usual commands. Escape returns to the terminal.
  6. Select text in review mode with Shift and the arrow keys; VO-F6 reads the selection and Command-C copies it.
  7. Command-F6 moves between the sidebar, the terminal and the status bar. In the session list, Up and Down Arrow move between sessions and Return opens one.
  8. Option-F1 lists the shortcuts for where you are. Help, then Terminal Remote Control Help, opens this guide in its own window.

Add a host

The sidebar's Hosts section has the New host field, with Add host to its right, and an optional User field below.

  1. Type the host as you would after ssh: an alias from your SSH config (devbox), or user@host, host:port or user@host:port. As you type, TRC offers hosts you added before and the Host entries of your ~/.ssh/config and the files it includes; press Down Arrow to pick one.
  2. To log in as another user, type it in User, or put it in the host as user@host (not both).
  3. Press Return or choose Add host.

TRC connects to the new host at once. The first time, it installs the daemon under ~/.trc on the host, which takes a few seconds; each step shows in the host's state and is announced.

Trust a host key

When your known_hosts doesn't know the host yet, a dialog shows the host, its key type and the SHA-256 fingerprint in a field you can select and copy. Compare it with one you got from the host's owner, then choose Trust, which adds the key to ~/.ssh/known_hosts, or Reject (or press Escape). Take as long as you need: the question never times out.

TRC refuses a host whose key changed. If you expected the change, remove the old key yourself (ssh-keygen -R <host>) and connect again.

Host actions

Open a host's actions with Shift-F10, the Menu key or Control-click on it in the Hosts list or the Sessions list, or find them in the command palette:

  • New session, Connect, Disconnect or Cancel connecting.
  • Test connection: connects, says whether it works, and disconnects again.
  • Change install location: for a host whose home folder can't run programs (mounted noexec), pick another folder, such as one on another disk. The next connection uses it. Only you, or root, may be able to change that folder and each folder above it; a shared folder is fine only with the sticky bit, as /var/tmp has. TRC refuses a location other users could change, since they could swap the daemon it runs.
  • Forget: removes the host from TRC after you confirm. Its sessions keep running on the host, and adding the host again shows them.

Connect

When the app opens, it connects to every known host. A host that fails stays disconnected and shows no dialog.

Each host in the Hosts section shows its state as an icon and as text: Not connected, Connecting, Connected, Connection failed or Disconnected. Its button connects, cancels or disconnects it.

If your key is a security key, TRC shows and says "Touch your security key for <host>" while ssh waits for the touch.

When a working connection drops, TRC says "Connection to <host> lost" and lists it in the notifications. The host's sessions stay in the list, marked Disconnected, and their terminals take no input: a key press is not sent and not kept for later, and TRC shows and says "Disconnected — input not sent". Choose the host's Connect button to reconnect: the sessions still running on the host come back, and each open terminal attaches to its session again.

When a connection you started fails, a dialog names the host, explains the reason (for example, the agent has no key the host accepts, the host is unreachable, or the connection timed out) and offers the details ssh reported. Choose OK to close it.

Sessions

The Sessions list is a tree: each connected host, then its sessions. It is one stop for Tab.

  • Opening. Moving through the list doesn't switch sessions. Opening one moves focus to its terminal, and TRC says its name, host and state, and whether it has output you haven't seen.
  • States. Each session shows Starting, Running, Exited (with the exit code or signal), Stopped or Failed to start, and "new output" while it has output you haven't seen. VoiceOver reads its position, such as "2 of 3".
  • New session with options. Choose the host, the shell, the working folder, a name, and environment variables (one NAME=value per line; NAME= removes a variable).
  • Session actions. Rename (an empty name shows the title the program sets), Stop, Restart (same shell, folder and environment; the scrollback stays), Duplicate (same shell and folder), Move up, Move down, and Close, which asks first because it deletes the session and its scrollback. You can also drag a session up or down its host's list. The command palette lists the open session's actions too.
  • Ending a session. Type exit, or end its program. A session that exits cleanly (code 0) leaves the list, unless you turn off "Close sessions that exit cleanly" in Settings; one that failed stays, so you can read its last output.
  • Stopping. Stop asks the program to end, then forces it after the seconds Settings sets (5 by default).

Sessions keep running on the host when you quit the app or the connection drops. When the app connects again, it lists them, and opening one shows its screen as the host has it now. A host reboot ends them in this release.

The terminal

The terminal takes every key you type, including Escape, Tab and the arrow keys, and sends it to the session. The Command key belongs to the app.

ActionKeys or gesture
Copy the selectionCommand-C. Wrapped lines come out as the program printed them
PasteCommand-V. More than one line asks first and says how many
Copy, Paste, List Links and Look UpShift-F10, the Menu key, Control-click or right-click
Select textDrag. Drag past the top or bottom edge to scroll; farther is faster

Programs that ask for the kitty keyboard protocol (Claude Code, Neovim, Helix and others) receive modified keys such as Shift-Return and Control-Tab as distinct keys. Others receive the classic xterm codes.

The terminal sets TERM=xterm-256color, COLORTERM=truecolor and TERM_PROGRAM=trc, and resizes the session's PTY to fit the window.

Programs can't read your clipboard, and by default they can't write it either. To let a host's programs write it (for example tmux or Neovim copying over OSC 52), turn on that host's switch in Settings, under Hosts; TRC then says each time a program puts text on the clipboard.

A selection of more than 5,000 lines still copies whole; VoiceOver sees its first 5,000 lines, and TRC says so. Pasting more than one line shows the text and asks first, because the shell may run each line. Programs that ask for bracketed paste, such as bash and zsh, then wait for Return before they run anything.

When you scroll back, the terminal stays where you are while output arrives, and a "New output below" button appears (TRC says so once). Click it, press Shift-Page Down to the end, or type to return to the bottom.

The bell never flashes: the status bar shows "Bell" for a few seconds and TRC says it, with a short tone when sound cues are on. A session in the background gets a "bell" badge in the session list instead, until you open it.

Review mode and Find

Option-F2 opens review mode: the whole scrollback and screen as a read-only text field over the terminal, with the caret on the cursor's line. VoiceOver reads it by character, word, line and paragraph, a braille display follows the caret, and Shift with the arrow keys selects text for Command-C. Command-Up and Command-Down go to the start and the end; output that arrives meanwhile doesn't move you, TRC says "New output" once, and Command-Down brings it in. Option-F2 or Escape returns to the terminal; review mode never sends keys to the program.

Command-F opens Find above the terminal. Type to search, from the most recent output back; Return finds the previous match and Shift-Return the next. Match case and Regular expression narrow it. TRC selects each match, says "Match 3 of 17", and in review mode moves the caret to it. Escape closes Find and returns where you were.

Links

Command-click a web address in the terminal, or a link a program prints (such as ls --hyperlink), to open it with the app macOS assigns to it, such as your browser. Shift-Command-O lists the links on the screen, so you can open one from the keyboard.

Programs decide what links say, so TRC first shows the full address and asks. When the link's text differs from its address, the dialog says so. Choose "Always open links that start with https://example.com" to trust that site: from then on its links open without asking. TRC keeps the trusted prefixes in accept_urls.json (see Files and folders). Links without a site, such as mailto: or file: links, always ask. TRC never opens javascript: or data: links.

  • Notifications. Connection failures and lost connections stay in the list until you dismiss them, including failures while connecting at launch. TRC also says when a host connects or its connection is lost.
  • Menus. View and Terminal hold the same commands, with their Command shortcuts.

Appearance

  • Theme. View, then Theme: Midnight (the default, black with green, high contrast), System (follows macOS light or dark), Light, Dark, High contrast light and High contrast dark. TRC also follows the macOS Increase contrast and Reduce motion settings.
  • Terminal text size. Command-= makes the terminal text bigger, Command-- smaller and Command-0 returns it to the default, in steps of 10% from 50% to 200% (also in the Terminal menu). Every session follows, resizes to fit, and TRC says the new size and remembers it.
  • Cursor and spacing. The cursor is a block that doesn't blink. Settings, under Terminal display, changes its shape (block, bar or underline), the bar's width (1 to 6 pixels), blinking, the line height (1 to 2) and the letter spacing (0 to 4 pixels). A blinking cursor stops after 5 seconds without typing, and never blinks while macOS Reduce motion is on.
  • Window size. View, then Zoom In (Control-Command-=), Zoom Out (Control-Command--) and Actual Size (Control-Command-0) scale the whole window, sidebar included. Option-Command-= and - stay macOS Zoom's.
  • Sidebar width. Drag the sidebar's right edge, between 300 and 800 pixels. Or focus the edge with Tab and use Left and Right (10 pixels per press), Home (narrowest) and End (widest); Enter hides the sidebar and shows it again. TRC remembers the width and whether the sidebar is hidden.

Accessibility

  • VoiceOver reads the terminal as a text field holding the screen's text, by character, word or line. The text field's cursor is the terminal's cursor, so VoiceOver and Zoom follow it as you type.
  • Selection in the terminal is real text selection, so Speak Selection, Look Up and Services work on it.
  • Keyboard. Every control works with the keyboard, with a visible focus ring, and the terminal never traps focus: Command-F6 always leaves it, and Tab focus mode lets Tab leave it too.
  • Accessibility help. Option-F1, or Help, then Accessibility Help, lists the shortcuts for where you are (the terminal, review mode or the session list), then those that work everywhere, with the shortcut each command has now. Its User guide button opens this guide.
  • User guide. Help, then Terminal Remote Control Help, opens this guide in a window of its own, as headings, lists and tables that VoiceOver reads like any web page.
  • Announcements. Status changes, such as Tab focus mode or a host connecting, are spoken without moving focus.
  • Spoken output. In screen-reader mode, TRC speaks the open session's new output as it arrives, line after line, without moving focus:
    • It doesn't repeat what you type, which VoiceOver already echoes.
    • Sessions in the background stay silent. Shift-Command-A mutes and unmutes the open session.
    • When more than 20 lines arrive in a second, TRC stops reading line by line and, once the output pauses, says how many lines arrived, such as "312 lines of output".
    • In full-screen programs such as vim, less and htop, it reads the line at the cursor when the cursor moves to another line or that line changes.
    • Pressing any key drops the output still waiting to be spoken.

  • Screen-reader mode turns on by itself when VoiceOver or other assistive technology starts using the app, and TRC says so. To force it, pick On or Off for Screen-reader mode in Settings, or choose "Screen reader mode: on", "Screen reader mode: off" or "Screen reader mode: automatic" in the command palette (Shift-Command-P); TRC remembers the choice. For one launch, start the app with the flag:

    open -a "Terminal Remote Control" --args --screen-reader-mode=on
  • Voice Control can choose every button by its name, for example "Click New session on devbox".
  • Fonts. TRC embeds Atkinson Hyperlegible Next for the interface and Intel One Mono for the terminal.

Files and folders

On your Mac, TRC keeps its settings in the TRC home, ~/.trc:

FileHolds
config.jsonYour settings, the screen-reader mode, and the sidebar's width (sidebarWidth, 300 to 800) and whether it is hidden (sidebarCollapsed)
hosts.jsonThe known hosts, and per host allowClipboardWrites (off unless true)
accept_urls.jsonThe link prefixes you trust, as a JSON list such as ["https://github.com/myteam/"]. A prefix matches up to a /, ? or #, so https://github.com never matches https://github.com.evil.example

Both files are readable only by you. Edit config.json while the app is closed; a value TRC can't use falls back to its default.

To use another folder, set TRC_HOME when you start the app. A leading ~ means your home folder, and a relative path lies under it:

TRC_HOME=~/work/trc open -n "/Applications/Terminal Remote Control.app"

Logs and Chromium's own data stay in ~/Library/Application Support/Terminal Remote Control. Logs never hold terminal output, keystrokes, environment values or keys.

On each host, the daemon lives in ~/.trc: its binaries under versions/, its socket under run/ and its logs. To remove TRC from a host, end its sessions, then delete ~/.trc there.

The licenses of the software TRC includes are in the app, in Terminal Remote Control.app/Contents/Resources/notices/THIRD_PARTY_NOTICES.txt; Electron's and Chromium's are in LICENSE.electron.txt and LICENSES.chromium.html beside it.

What's not there yet

Later epics add sessions that survive a host reboot, local sessions on the Mac, macOS hosts, and the Windows and Linux apps. The PRD has the full plan.
