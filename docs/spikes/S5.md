# Spike S5 — Bootstrap on Ubuntu, Alpine/busybox and Rocky

| Field    | Value                                                               |
| -------- | ------------------------------------------------------------------- |
| Date     | 2026-11-12                                                          |
| Story    | ST-1 (E1)                                                           |
| Retires  | R10's mechanism (restrictive hosts), the US-1.4 install path        |
| Decision | The TECH_STACK §7 bootstrap works as designed, with the fixes below. |

## What was built

A POSIX `sh` prototype (`spikes/s5/bootstrap.sh`) piped to `exec /bin/sh -s` over `ssh -T`, plus a small driver that
plays the app's side. The app prepends `nonce=…` and `root=…`, waits for `HELLO`, then sends
`UPLOAD <size> <sha256> <version>` followed by exactly `size` bytes, and finally `RUN <sha256>` or `EXIT`. The
stand-in binary was the 2.5 MB static musl build from S1.

Hosts: Ubuntu 24.04 (bash, GNU coreutils), Alpine 3.23 (busybox `ash`, no bash, no `getent`), Rocky 9.8, a home
directory mounted `noexec`, and an NSS-only user (libnss-extrausers, not in `/etc/passwd`). All arm64 in the `trc`
colima profile.

## Results

| Case                                   | Result                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------- |
| Fresh install, Ubuntu / Alpine / Rocky | `INSTALLED <sha256>` in 0.10–0.14 s after the first byte over loopback ssh |
| NSS-only user                          | Installs; sshd sets `HOME` and `SHELL` through NSS                         |
| Second connection                      | `HELLO … installed=<sha256>`, so the app can skip the upload               |
| Corrupted upload                       | `ERROR checksum mismatch`; staging directory and lock removed             |
| Short upload (stdin closed early)      | `ERROR short upload 1254968 of 2509936 bytes`; staging and lock removed   |
| `noexec` home                          | `--version` exits 126 → `ERROR noexec /home/tester/.trc`                  |
| `noexec` home, root `/var/tmp/trc-<uid>` | Installs and runs (the per-host install location works)                 |
| Startup-file noise (`echo` in `.bashrc`) | Printed before the nonce line and discarded by the driver               |

Tool availability: `sha256sum`, `head -c`, `mktemp -d` and `mkdir` locking exist on all three. Alpine has no
`getent`, Rocky also has `openssl`.

NSS-only user: a static musl binary's `getpwuid()` returns NULL for uid 2001, while `$SHELL` (from sshd) and
`getent passwd 2001` return `/bin/bash`. This confirms TECH_STACK §8: the daemon uses `$SHELL`, then
`getent passwd $(id -u)`, then `/bin/sh`.

## Stdin discipline

The script and the binary share one stdin. That is safe only if nothing reads ahead:

- The app sends nothing after the script until it has read `HELLO`, so the shell's parser has no extra bytes
  buffered when `main` runs.
- `read` reads its command line byte by byte; `head -c N` reads at most N bytes.
- The app waits for `INSTALLED` before it sends `RUN`.

## Fixes for ST-7

- **Leave nothing behind.** On failure the prototype removed the staging directory and the lock but left the empty
  `root/` and `root/versions/` it had created. The production script records which directories it created and
  removes them (if still empty) in the failure trap, so US-1.4.4 holds.
- `sleep 0.2` in the lock loop works on GNU and busybox but is not POSIX; use `sleep 1`.
- Report `uname -s`, `uname -m` and the missing tool in every error, so the US-1.4.4 message names what is missing.
- The `noexec` message names the install root and points to the per-host install location setting (R10).
- `dd bs=1` is the fallback when `head -c` is missing; it is slow (one syscall per byte) but no tested host needs it.
