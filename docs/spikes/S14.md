## What was built

- `crates/trcd/shell-integration/`: TRC's bash, zsh and fish scripts, which ST-65 embeds and injects. They were run
  by a throwaway harness (a Python PTY driver, P-06) with a cleared environment as the holder starts shells, a scratch
  home whose dotfiles set `PS1`, `PROMPT_COMMAND` and a zsh `precmd` hook, and the commands `echo hi`, `false`, an
  empty Return, `cd` into a folder with a space, and Ctrl+C at the prompt.
- `crates/trc-vt/src/marks.rs`: the marks kept on tracked rows and written back into snapshots and saved history
  (P-74), built test-first as ST-66 will keep it.

## Results

- **bash 4 and later, `--posix` with `ENV`** (Ubuntu 24.04's 5.2.21, Alpine 3.23's 5.3.3, Rocky 9's 5.1.8), login
  and non-login: the startup files bash itself would read run once (`/etc/profile` and `.bash_profile` for a login
  shell, `/etc/bash.bashrc` or `/etc/bash/bashrc` and `.bashrc` otherwise; `/etc/bashrc` is left to the user's
  `.bashrc`, so Rocky reads it once); POSIX mode is off afterwards (`shopt -o posix` reads off), a login shell stays
  one (`shopt login_shell` on, `logout` at exit), `ENV` is gone, and `HISTFILE` is `~/.bash_history` again, as bash
  5.2 in POSIX mode starts with `~/.sh_history`.
- **bash 3.2, macOS `/bin/bash`, with `--rcfile`**: a login is emulated by sourcing `/etc/profile` and the first of
  `.bash_profile`, `.bash_login` and `.profile`; the `DEBUG` trap marks the command start.
- **zsh 5.8 (Rocky), 5.9 (Ubuntu, Alpine, macOS)** with `ZDOTDIR`: the user's `.zshenv`, `.zprofile` and `.zshrc`
  run from their own `ZDOTDIR` or home, which is put back first; the hooks go in at the first prompt, after the
  user's, and a user `precmd` still sees each command's status. zsh's `path` parameter is tied to `PATH`, so the
  script's locals avoid it.
- **fish 3.7 (Ubuntu)** with `XDG_DATA_DIRS`: `vendor_conf.d` runs before `config.fish`; the script puts
  `XDG_DATA_DIRS` back and marks prompts, commands and ends, and reports OSC 7. **fish 4.0.2 (Alpine)** marks
  everything itself (`133;A;special_key=1`, `133;C;cmdline_url=…`, `133;D;<status>`), so the script adds nothing;
  its command line in `cmdline_url` is ignored (P-75).
- **Marks in every case**: a prompt is `D;<status>` of the last command (bash always sends one; zsh and fish only
  after a command), OSC 7, `A` and, from `PS1`, `B`; a command is `C`. An empty Return or Ctrl+C sends no `C`, so its
  `D` is dropped. bash 4.4 and later mark the start with `PS0`, which an empty line does not print. A user's own hook
  in `PROMPT_COMMAND` or `precmd` still reads the command's status.
- **libghostty-vt's semantic-prompt callback** reports prompt, input, output and end, the exit code with the end,
  and the screen is updated when it runs, so the cursor's row is the marked row. Rows tracked from the callback follow
  scrolling and a reflowing resize, and drop out when the scrollback prunes them. Repairs that make a second
  integration harmless (a prompt redrawn on its row counts once, an end needs a start, a repeated start or end counts
  once) are tested.
- **Marks through a snapshot and a save and restore**: written before the rows they mark in the history blocks, and
  after the screen with cursor moves, a replayed terminal has the same marks on the same rows, in a snapshot streamed
  seven rows at a time and in saved history taken four rows at a time.
- **Cost**, 6,000 commands of 10 lines each in a 120 × 40 terminal with a 100,000-line scrollback (release build,
  this Mac): feeding 12 ms with marks against 9 ms without, a full snapshot 14 ms against 11 ms, with the 3,000 marks
  kept (P-74's bound of 1,000 commands). A first version that pruned the log on every step took 6 s to feed; marks
  are kept in row order, so a binary search finds a block's.
- **Privacy prompts (ST-64, item 6).** The TCC log (`log show --predicate 'subsystem == "com.apple.TCC"'`) shows
  every request for Desktop, Downloads and Documents made by Claude Code running in a local session, with `trcd`
  named as the responsible process, as launchd started it; TRC itself opened none of them. macOS names the app or
  daemon that started a program, as it names Terminal for Terminal's windows, and with ad-hoc signatures each daemon
  version is a new identity, so the questions come back after an upgrade. P-66 stands; the user guide now says why
  `trcd` is named.
- **OS notifications (P-76)** were not posted here, as a test notification would ask the owner's permission for a
  throwaway app; ST-68 checks Electron's `show` and `failed` events on the packaged, ad-hoc-signed build and keeps
  every event in the in-app list whatever macOS answers.
