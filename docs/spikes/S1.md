## What was built

A throwaway Rust binary (`spikes/s1`, committed once as evidence) linked statically against libghostty-vt 1.0.1:

- Source and dependency tarballs from `release.files.ghostty.org/libghostty-vt/1.0.1/`, verified with minisign
  against the Ghostty release key `RWQlAjJC23149WL2sEpT/l0QKy7hMIFhYdQOFy0Z7z7PbneUgvlsnYcV` and against the signed
  `SHA256SUMS`.
- `zig build --system <deps> -Doptimize=ReleaseFast -Dcpu=baseline -Dtarget=<triple>` with Zig 0.17.1, fully
  offline, for `aarch64-macos`, `x86_64-linux-musl` and `aarch64-linux-musl`.
- Bindings generated once with bindgen 0.73.2 (`--no-doc-comments --use-core --default-enum-style moduleconsts`),
  3,518 lines.
- Linked with `cargo zigbuild` for both musl targets, and natively on macOS.

## Results

### Build and link

| Target                     | Static lib | Linked binary (stripped, LTO, with portable-pty) |
| -------------------------- | ---------- | ------------------------------------------------ |
| aarch64-apple-darwin       | 12.6 MB    | 1.6 MB                                           |
| aarch64-unknown-linux-musl | 22.4 MB    | 2.5 MB, statically linked                        |
| x86_64-unknown-linux-musl  | 22.7 MB    | 2.9 MB, statically linked                        |

- The archive needs only libc symbols; no C++ runtime.
- **Pitfall:** the install directory holds both `libghostty-vt.a` and the dylib, and the macOS linker picks the dylib
  even with `rustc-link-lib=static=`. The build script must link from a directory that holds only the `.a`.
- The same corpus output (byte-identical JSON) on macOS, Alpine 3.23 and Ubuntu 24.04, arm64 natively and x86_64
  under Rosetta.

### VT round trip into xterm.js

Each sample goes into libghostty-vt, is formatted as VT, and is replayed into `@xterm/headless` 6.0.0 with
`@xterm/addon-unicode-graphemes` 0.4.0 (`15-graphemes`). The replay is compared with xterm.js fed the original bytes:
viewport row text, cursor position, per-cell widths, buffer type and the whole normal buffer.

Corpus (80×24): CJK with wrapping, emoji (ZWJ family, flag, skin tone, VS16, keycap, text presentation), combining
marks (Latin, Hangul, Devanagari, Thai, zalgo), a wide grapheme at the right margin, the alternate screen, SGR
colors and styles with an OSC 8 link, terminal queries, titles and bell, 300 lines of scrollback, `ls --color` over
`/usr/bin`, and vim, htop and less captured from the Ubuntu host, each also cut while still on the alternate screen.

- **15 of 16 samples match exactly** once DEC mode 2027 (grapheme clustering) is on.
- With mode 2027 off (the library default), the keycap `1️⃣` loses its VS16 and a ZWJ sequence at the right margin is
  split across two rows. **The holder must turn mode 2027 on by default** (`GHOSTTY_TERMINAL_OPT_MODE_DEFAULT`).
- The one remaining difference is vim writing `👍` and `🏽` as two separate cells with cursor moves between them,
  because vim thinks each is two columns wide. The two emulators then disagree about an empty wide cell after the
  emoji (two trailing spaces versus an empty wide cell). The visible text is the same. This is a program/terminal
  width disagreement, not an engine defect.
- **The VT formatter must run with `TRIM=false`** and `EXTRAS_ALL`. With the default trim, trailing blank rows are
  dropped and the replayed viewport is off by one line.

### Query replies (effect callbacks)

All replies arrive through `WRITE_PTY`:

| Query                      | Reply                                                          |
| -------------------------- | -------------------------------------------------------------- |
| DA1 `CSI c`                | `CSI ? 62 ; 22 c`                                              |
| DA2 `CSI > c`              | `CSI > 1 ; 0 ; 0 c`                                            |
| CPR `CSI 6 n`              | `CSI 1 ; 1 R`                                                  |
| XTVERSION `CSI > 0 q`      | `DCS > \| trcd 0.0.0 ST` (callback)                            |
| OSC 10 / OSC 11 `?`        | `rgb:dddd/dddd/dddd`, `rgb:1111/1111/1111` (configured colors) |
| DECRQM `CSI ? 2004 $ p`    | `CSI ? 2004 ; 2 $ y`                                           |
| Title report `CSI 21 t`    | none (SEC-06.3)                                                |
| OSC 52 read                | none (SEC-06.1)                                                |
| Size reports `CSI 14/18 t` | none while the size callback declines                          |

vim's startup queries (OSC 11, the kitty keyboard query, DA1) were all answered. Title changes and BEL arrive through
their callbacks.

### Memory per holder (PSS, Ubuntu container, 120 columns)

| Holder state                       | arm64   | x86_64 (Rosetta) |
| ---------------------------------- | ------- | ---------------- |
| Idle, empty terminal               | 1.4 MB  | 2.7 MB           |
| 10,000 lines of scrollback         | 11.0 MB | 12.5 MB          |
| 100,000 lines written, 10,000 kept | 12.0 MB | 13.5 MB          |

- The per-session overhead beyond scrollback is 1.4–2.7 MB, inside NFR-09's 10 MB.
- 10,000 lines of 120 columns take about 10 MB, as TECH_STACK §5.3 expected (NFR-10).
- **Pitfall:** the default scrollback byte limit is 10,000 bytes (one page, about 400 rows). The holder must set
  `SCROLLBACK_MAX_BYTES` to `SIZE_MAX` and bound history with `SCROLLBACK_MAX_LINES`.
- The line limit is page-granular: 10,000 requested kept 9,972–9,977 rows.
- `ghostty_terminal_compress` exists for idle scrollback and is a later lever if 100,000-line sessions need it.

## Consequences for the plan

- D-02 stands: libghostty-vt in the daemon, alacritty_terminal stays the unused fallback.
- ST-4 (`trc-vt`) sets, for every terminal: mode 2027 on by default, unlimited scrollback bytes with the configured
  line limit, the XTVERSION callback, foreground and background colors for OSC 10/11, and a formatter with VT output,
  `EXTRAS_ALL` and `TRIM=false` for snapshots.
- ST-4's `build.rs` builds the static library into `OUT_DIR` and links from a directory with only the `.a`.
- The corpus moves into `crates/trc-vt` test fixtures, and the xterm comparison becomes a Vitest check in
  `@trc/protocol` or the renderer tests.
