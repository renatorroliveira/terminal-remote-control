# Spike S11 — systemd service mode, kill scope and logout

| Field    | Value                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------ |
| Date     | 2026-11-14                                                                                       |
| Story    | ST-23 (E2)                                                                                       |
| Retires  | R4, R5 and R6 on Linux (mechanism); the US-2.4 and US-2.5.1–2 design                             |
| Decision | D-44 as written, including the user-manager rule for `KillUserProcesses=yes` (owner, 2026-11-14) |

## What was built

An Ubuntu 24.04 container with systemd as PID 1, logind, `libpam-systemd` and `dbus-user-session`, on the `trc`
colima profile with its port on `127.0.0.1`. systemd needed `--privileged --cgroupns=private`: without it the
container exited at once. Two users: `tester` (lingering off) and `lingerer` (lingering on, from
`/var/lib/systemd/linger`). Each probe ran over a real ssh login, so pam_systemd made a logind session for it.

## Results

| Case                                                                             | Result                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Detection                                                                        | `loginctl show-user <user> -p Linger` and `busctl get-property org.freedesktop.login1 /org/freedesktop/login1 org.freedesktop.login1.Manager KillUserProcesses` answer over ssh; `XDG_RUNTIME_DIR` is set and `systemctl --user` works |
| Lingering off, `KillUserProcesses=no`: detached process (`setsid`) at logout     | Survives; the session stays `closing` and the user manager stays up                                                                                                                                                                    |
| Lingering off, `KillUserProcesses=no`: process in a user-manager scope           | Survives too, because the `closing` session keeps the user manager alive                                                                                                                                                               |
| Lingering off, `KillUserProcesses=yes`: detached process                         | Ends when the connection that started it closes, even while another connection is open                                                                                                                                                 |
| Lingering off, `KillUserProcesses=yes`: process in `systemd-run --user --scope`  | Survives while any connection is open; ends about 10 s after the last one closes (`UserStopDelaySec`)                                                                                                                                  |
| Lingering on: transient unit `systemd-run --user --unit … -p Restart=on-failure` | `kill -9` of its main process restarts it within 0.2 s (`NRestarts=1`)                                                                                                                                                                 |
| Lingering on: holder in `systemd-run --user --scope` under that unit's process   | Survives `kill -9` of the unit and `systemctl --user stop`, which removes the transient unit                                                                                                                                           |
| Lingering on: every connection closed                                            | The unit and every scope survive; the user manager stays up                                                                                                                                                                            |

## Consequences

- With lingering on, the core runs as a transient unit restarted on failure and each holder starts in its own
  transient scope. `RestartPreventExitStatus` must name 75 (another core runs) and 78 (untrusted install), so a
  refused start does not loop.
- With `KillUserProcesses=yes` and lingering off, a detached core and its holders would end with the connection
  that started them. Running them under the user manager keeps them until the last connection closes, which is
  what US-2.4.4 tells the user; the owner chose this on 2026-11-14 (D-44, the US-2.4 E2 note).
- Otherwise, detached stays right: it survives logout, and a user-manager scope would gain nothing.
- The systemd test host (P-32) needs `--privileged`; it runs on the local test VM only, like the others.
