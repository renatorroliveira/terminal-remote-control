# Spike S3a — Local floods with accessibility on

| Field    | Value                                                                                                |
| -------- | ---------------------------------------------------------------------------------------------------- |
| Date     | 2026-11-12                                                                                           |
| Story    | ST-1 (E1). S3b (100 ms RTT, credit window) runs in ST-19.                                            |
| Retires  | R2 and R9 in part (renderer and AX update cost), initial values for A11Y-02.3, A11Y-03.2, A11Y-04.7  |
| Decision | Keep the TECH_STACK cadence: per frame without AT, at most 4 per second with AT, held during floods. |

## Setup

The S2 prototype (Electron 45, xterm.js 6 WebGL, ATS) fed by a local child process over IPC, with xterm's write
callbacks pausing the child above 512 KiB pending and resuming below 128 KiB. "AX on" means
`app.setAccessibilitySupportEnabled(true)`, which makes Chromium build and serialize the accessibility tree for every
ATS change. Each run lasted 8 s on Apple silicon, with renderer and occlusion throttling off.

## Results

| Flood                      | AX  | ATS cadence     | Throughput | Frame p95 / max | Long tasks | ATS updates/s |
| -------------------------- | --- | --------------- | ---------- | --------------- | ---------- | ------------- |
| `yes`                      | off | per frame       | 6.8 MB/s   | 10.8 / 40 ms    | 0          | 39            |
| 1 GB of 90-character lines | off | per frame       | 91 MB/s    | 10.9 / 31 ms    | 0          | 81            |
| `find /`                   | off | per frame       | 1.9 MB/s   | 10.8 / 11 ms    | 0          | 28            |
| `yes`                      | on  | 250 ms + hold   | 7.0 MB/s   | 10.8 / 40 ms    | 0          | 2.7           |
| 1 GB of 90-character lines | on  | 250 ms + hold   | 97 MB/s    | 11.0 / 21 ms    | 0          | 0             |
| `find /`                   | on  | 250 ms + hold   | 1.9 MB/s   | 10.7 / 11 ms    | 0          | 0.1           |
| `yes`                      | on  | per frame       | 8.1 MB/s   | 10.7 / 30 ms    | 0          | 49            |
| `yes`                      | on  | 250 ms, no hold | 10.8 MB/s  | 10.7 / 31 ms    | 0          | 3.6           |

- The UI never blocked: no long task over 50 ms in any flood, and frame p95 stayed at the display rate. `yes` is
  bound by xterm's parser (many short lines), the 1 GB stream by IPC.
- The flood hold (no ATS update while output exceeds 256 KiB/s, released 500 ms after it drops) keeps the AX tree
  still during a flood, as A11Y-02.3 needs. The owner's VoiceOver session flagged no responsiveness problem; timed
  VoiceOver measurements under a flood (NFR-04) are part of S3b in ST-19.

## Echo suppression (R9)

The prototype echoed typed text locally, and VoiceOver did not double characters, because the ATS makes no
announcements yet. Output announcements arrive in ST-14, which implements echo suppression on the logical-line
announcer and re-checks R9 with VoiceOver.
