# E2 security checklist (SEC-01 to SEC-08)

What E2 changes against PRD §8.2, with the evidence that each item still holds; items E2 does not touch keep
E1's evidence (`E1-security.md`). The suites are `pnpm check`, `pnpm test:integration`, `pnpm test:daemon`,
`pnpm test:e2e`, `pnpm test:nfr`, `pnpm test:soak` and `pnpm verify:artifact`.

| Item     | What E2 adds                                                                | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Status |
| -------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| SEC-01.1 | Reconnecting, restore and the quit flow open no socket                      | They reuse the ssh process and the MessagePorts; `no-listeners.spec.ts` finds no listener and no UDP socket after connect and create and again after a forced reconnect, and `verify:artifact` checks the release build; restore and the quit flow add no network code (they read `sessions.json` and post IPC); D-47 changes only renderer task scheduling                                                                                                                                             | Met    |
| SEC-01.2 | The core as a systemd user unit, and holders in scopes                      | Same socket, same modes; the unit gets the user's login umask (`UMask=`, `service.rs` unit test of `unit_arguments`), and `service.integration.test.ts` runs the core and its holders under systemd on the systemd test hosts                                                                                                                                                                                                                                                                           | Met    |
| SEC-02.1 | Several apps attach to a session                                            | Every attachment comes through the core's socket, whose peer check (`core/service/mod.rs`) is unchanged and still refuses another user (`core_linux.rs`, `holder_process.rs`, run as root in the containers by `pnpm test:daemon`); `core_shared.rs` covers several apps on one session; another computer reaches it only over the user's own SSH                                                                                                                                                       | Met    |
| SEC-03.1 | Automatic reconnects                                                        | Each attempt runs the same ssh arguments (`arguments.test.ts`); failures that need the user (authentication, host keys, an incompatible daemon) stop retrying, so nothing ever prompts or relaxes host-key checking (`retry-policy.test.ts`, `reconnector.test.ts`)                                                                                                                                                                                                                                     | Met    |
| SEC-04.4 | The bridge runs another installed daemon to upgrade, or to read its version | It runs one only after the integrity check and once its SHA-256 matches its folder name (`trustworthy()` in `upgrade.rs`; `--version` answers before a binary's own check, so this is its only guard); `upgrade.rs` tests run a newer intact binary and refuse a misnamed, `.staging.*` or writable one, refuse to stop a process outside `versions/`, stop nothing once another core holds the lock, and read no core from an unparsable lock; one bridge at a time replaces the core (`upgrade.lock`) | Met    |
| SEC-05.1 | `sessions.json` keeps each host's session list                              | 0600, written atomically, read and accepted over IPC only through zod; it holds the ID, name, title, shell name, order and state, never a working folder, environment value or process ID (the title is what the program set, as the session list shows it); text is clipped and sessions capped so a save never fails on size (`session-cache.test.ts`, `ipc.test.ts`, `restore.spec.ts` checks the file's mode and contents)                                                                          | Met    |
| SEC-06.2 | Output from other clients, and replays                                      | `peerInput` only announces; replays and resyncs are never spoken and act on nothing (`output-announcer.test.ts`, `terminal-view.test.ts`)                                                                                                                                                                                                                                                                                                                                                               | Met    |
| SEC-07.1 | Service mode                                                                | Lingering is used only when it is already on; the app never enables it (D-44, `service.integration.test.ts`). Beyond the install root, only what systemd keeps for any transient unit is written: its unit file under `$XDG_RUNTIME_DIR/systemd/transient`, gone at logout, and the journal's start and stop lines                                                                                                                                                                                      | Met    |
| SEC-08.1 | Reconnect, restore, sharing and upgrade logs                                | They log failure kinds and states, never output or input; `canary.nfr.test.ts` runs over the E2 paths too                                                                                                                                                                                                                                                                                                                                                                                               | Met    |
| IPC      | New channels `sessions:*`, `app:quit` and `app:quit-notice-opened`          | Validated with zod and accepted only from the app's page (`ipc.test.ts`); `sessions:save` refuses any field beyond the list's                                                                                                                                                                                                                                                                                                                                                                           | Met    |
