# E3 security checklist (SEC-01 to SEC-08)

What E3 changes against PRD §8.2, with the evidence that each item still holds; items E3 does not touch keep the
evidence of `E1-security.md` and `E2-security.md`. The suites are `pnpm check`, `pnpm test:integration`,
`pnpm test:daemon`, `pnpm test:e2e`, `pnpm test:nfr`, `pnpm test:soak` and `pnpm verify:artifact`.

| Item     | What E3 adds                                                           | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Status |
| -------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| SEC-01.1 | Restore, Restart daemon and Remove daemon open no socket               | Restored holders use the same Unix sockets as E2's; Restart and Remove travel over the existing SSH channel, and `REMOVE` runs over a new SSH exec channel; `no-listeners.spec.ts` and `verify:artifact` are unchanged and pass                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Met    |
| SEC-02.1 | Restored sessions and the new requests                                 | Every request still comes through the core's socket and its peer check; `restartDaemon` and `removeDaemon` are refused before the handshake like any other request (`requests.rs`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Met    |
| SEC-03.1 | Upgrade daemon, and `REMOVE` over ssh                                  | Both run the same ssh arguments as a connection (`host-connection.ts` opens them through one path); a host key the removal has not seen stops it with "connect to the host first", so nothing prompts or relaxes host-key checking                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Met    |
| SEC-04.4 | Restored holders, and `REMOVE`                                         | A restored holder is started from the running core's own binary, as any holder; `REMOVE` runs only after the bootstrap's root and parent checks (`check_parents`, `check_root`), and kills only processes whose executable lies in this root's `versions/` (`stop_processes`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Met    |
| SEC-05.1 | Scrollback and session records on disk                                 | `sessions/` and each session's folder are 0700, `meta.json` and `scrollback.log` 0600, created by their owner only (`store.rs`, `scrollback_writer.rs` and `persistence.rs` tests check the modes); OQ-1 keeps user-only permissions as the control, with no encryption (D-05)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Met    |
| SEC-05.2 | What is stored, and deleting it                                        | "Save scrollback to disk" off writes no `scrollback.log` and keeps no program-set title in `meta.json`, and turning it off deletes the file; `meta.json` keeps what a restore needs: the shell, arguments and environment overrides the user gave, the name, size, order and options, the last known working folder (from OSC 7 or the OS, needed to restore the shell there, US-3.1.3), the state, exit status and failure text, and when it was last restored. Clear scrollback replaces the file with one holding only the screen; Close deletes the session's folder, even when the core ends before the holder does (the record is marked closing first); Remove daemon deletes `sessions/` (`persistence.rs`, `store.rs`, `restore.rs`, `manage.rs`, `bootstrap.integration.test.ts`) | Met    |
| SEC-07.1 | Removal deletes only what TRC wrote                                    | `REMOVE` deletes only the entries TRC creates in `versions/`, `sessions/`, `logs/` and `run/` (or the `/tmp/trc-<uid>` fallback the user owns), each by its name's shape, and `install.lock`, then each folder and the root only when empty; anything the user put there stays and is reported (`bootstrap.integration.test.ts`, P-46). Nothing outside the install location is registered, so nothing starts at boot (D-48)                                                                                                                                                                                                                                                                                                                                                                | Met    |
| SEC-08.1 | Restore, persistence and removal logs                                  | They log counts, session IDs and failure kinds, never output, input or environment values; a broken `meta.json` is logged by where it broke, not by what it holds (`store.rs`); a refused renderer request logs only its kind and the schema paths at fault (`router.test.ts`); `canary.nfr.test.ts` runs with persistence on, finds no canary under the daemon's `logs/` and `run/`, and finds every saved file 0600 and folder 0700                                                                                                                                                                                                                                                                                                                                                       | Met    |
| IPC      | `hosts:set-daemon-removed`, and `remove-daemon` to the connection host | The IPC channel is validated with zod and accepted only from the app's page (`ipc.test.ts`); the renderer's `remove-daemon` request is a strict zod schema at the connection host's boundary (`requests.ts`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Met    |
