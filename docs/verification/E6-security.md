# E6 security checklist, part 1 (0.7.0, SEC-01 to SEC-08)

What 0.7.0, the Windows app against remote hosts (US-6.1), changes against PRD §8.2, with the evidence that each item
holds on Windows; items it does not touch keep the evidence of `E1-security.md` to `E5-security.md`. Part 2 (0.8.0,
the Windows daemon) adds its own rows. The suites ran on Windows 11 against the Docker Desktop test hosts: `pnpm check`,
`pnpm test:integration`, `pnpm test:daemon`, `pnpm test:e2e`, `pnpm test:nfr` and `pnpm verify:artifact`; GitHub
Actions runs the gate and the packages on `windows-2025` and `windows-11-arm`; a row marked Pending waits for its
first run there.

| Item     | What 0.7.0 adds                                   | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Status   |
| -------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| SEC-01.1 | The Windows app, `trcd.exe`'s SSH helpers         | The app's processes and ssh children open no listener: `no-listeners.spec.ts` runs on Windows, reading Windows' TCP and UDP endpoint tables, and finds only the test build's Playwright debugging ports, in the main process; the helpers only read their arguments and write one line to stderr (`ssh_helper.rs`). The packaged app, launched with `--remote-debugging-port=0`, `--inspect=0` and `--inspect-brk=0`, holds no TCP listener or UDP endpoint in any of its processes (`verify-windows.ts`, run on each Windows runner) | Met      |
| SEC-01.3 | The listener check on Windows                     | `no-listeners.spec.ts` connects, creates a session and reconnects on Windows before each check; Playwright starts Electron through `cmd.exe` there, so the check reads the real main process's tree (`electronMainPid`)                                                                                                                                                                                                                                                                                                               | Met      |
| SEC-02.3 | Windows OpenSSH                                   | Remote access goes only through `C:\Windows\System32\OpenSSH\ssh.exe`, run by its absolute path so no PATH entry can shadow it (`platform-ssh.ts`); the product mints no token or secret                                                                                                                                                                                                                                                                                                                                              | Met      |
| SEC-03.1 | Windows ssh and its helpers                       | Every connection passes `BatchMode=yes`, so a hidden Windows ssh never waits for a passphrase (S9); `SSH_ASKPASS` runs `trcd.exe askpass`, which answers only ssh's notices and refuses every question (`ssh_helper.rs`); `KnownHostsCommand` runs `trcd.exe known-hosts`, which only reports the key, so host-key checking stays the app's, as on macOS; agent forwarding stays off. With the OpenSSH Authentication Agent off, the app says so and offers nothing to type (`windows-agent-off`)                                     | Met      |
| SEC-03.2 | Windows                                           | Nothing new is stored: the app reads `%USERPROFILE%\.ssh` through ssh and writes only the known-hosts file, after the user trusts a key                                                                                                                                                                                                                                                                                                                                                                                               | Met      |
| SEC-04.1 | Windows packages                                  | Pre-1.0 exception (P-87, D-43): unsigned until E8's Authenticode (US-8.3); the user guide says so and how SmartScreen warns                                                                                                                                                                                                                                                                                                                                                                                                           | Excepted |
| SEC-04.2 | `trcd.exe` and the bundled daemons                | `trcd.exe` ships inside the app; `verify:artifact` checks every bundled daemon, `trcd.exe` included, against the manifest's SHA-256 and size, and that `trcd.exe` is built for the app's own architecture (`verify-windows.ts`); the fuses and asar integrity validation are checked on the Windows program. libghostty-vt's source stays minisign-verified (D-14); the Windows runners' minisign comes from its signed release, pinned by SHA-256 (`.github/actions/windows-rust`)                                                   | Met      |
| SEC-05.1 | The TRC home and the app's data folder on Windows | Both get a protected DACL granting only the user's SID, inheritance from above off, and are marked not content indexed, so Windows Search keeps no copy (P-94, `windows_acl.rs` with its tests, `private-folders.ts`); state files are replaced by rename, retried only on a sharing violation (P-95, `json-store.ts`)                                                                                                                                                                                                                | Met      |
| SEC-06.2 | Windows copy, paste and context menus             | Copy and paste need the user's own keys or menus (P-86); Ctrl+C copies only when the user turned the setting on and a selection exists; a copy's CRLF conversion happens in the main process for the user's own Copy last command output, and OSC 52 writes are unchanged. A program can't open a menu: the Menu key's own `contextmenu` repeat is dropped (`menu-key-echo.ts`). Links open through `shell.openExternal` after the same confirmation as on macOS                                                                      | Met      |
| SEC-07.1 | The Windows installer and `trcd.exe private-dir`  | The NSIS installer is per user, with `allowElevation: false`; `verify:artifact` installs it and checks that it registers under HKCU only, never HKLM, then uninstalls it (`verify-windows.ts`); that check first runs on the release dry run's Windows runners; `trcd.exe private-dir` runs as the user                                                                                                                                                                                                                               | Pending  |
| SEC-08.1 | The Windows main process                          | It logs only the name of a folder it could not make private (`index.ts` `keepPrivate`); the helpers log nothing                                                                                                                                                                                                                                                                                                                                                                                                                       | Met      |
| SEC-08.2 | Log files on Windows                              | They live in the app's data folder, which the protected DACL above limits to the user                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Met      |
| Tooling  | The test hosts on Docker Desktop                  | `compose.yaml` publishes every test host's SSH on `127.0.0.1` only; `up.ts` gives `.run`, which holds the test keys, an ACL only the user holds (D-69)                                                                                                                                                                                                                                                                                                                                                                                | Met      |
